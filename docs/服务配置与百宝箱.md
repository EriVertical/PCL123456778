# 服务配置与百宝箱

使用本分支新构建的启动器，进入 **更多 → 百宝箱 → 服务配置**。已经下载的旧版 EXE 不会随源码更新，需重新构建。

## CurseForge API Key

1. 登录 [CurseForge 开发者控制台](https://console.curseforge.com/)，提交 API 访问申请，按要求填写应用用途并等待批准。
2. 从获批的应用中取得 API Key，粘贴到百宝箱的 **CurseForge API Key**，点击 **保存配置**。
3. 完全退出启动器后重新打开，在下载页选择 CurseForge，搜索一个 Mod 并打开版本列表，再尝试下载。

Key 仅保存到 `HKEY_CURRENT_USER\Software\PCLDebug\Services`，使用 Windows DPAPI 的 CurrentUser 范围加密。密码框不会回显已有 Key；下方会提示本地是否已保存并可解密，因此重启后输入框为空不代表 Key 被删除。留空保存会保留旧 Key，**清除本地 API Key** 才会移除。换 Windows 用户或重装系统后可能需要重新填写。不要将 Key 提交到 Git、发到聊天或打包进公开发行的 EXE；其他使用者可填写自己的 Key。

Key 只发送到 `https://api.curseforge.com` 的默认 HTTPS 端口，不发送到下载 CDN、镜像或名字相似的域名。401/403 应先检查 Key 是否有效、应用是否获批以及配额/权限。即使 Key 有效，作者禁用第三方分发的资源也可能无法下载；这需要使用 CurseForge 官方页面/客户端。

## Microsoft Client ID

1. 登录 [Microsoft Entra 管理中心](https://entra.microsoft.com/)，进入 **应用注册 → 新注册**，为自己的启动器注册应用。
2. 支持的帐户类型必须包含 **个人 Microsoft 帐户**，例如“任何组织目录中的帐户和个人 Microsoft 帐户”。本项目使用 `consumers` 设备码登录，组织帐户专用应用不适用。
3. 在应用的 **身份验证 → 高级设置** 开启 **允许公共客户端流**。设备码流程不使用 Client Secret，也不需要为本流程增加网页重定向 URI。不要把“客户端密码”“对象 ID”或“租户 ID”当作 Client ID。
4. 复制概述页的 **应用程序（客户端）ID**，粘贴到百宝箱的 **Microsoft Client ID**，保存并完全重启启动器。
5. 注册应用后还可能需要申请 Minecraft Java 服务 API 访问：[Minecraft 应用访问申请](https://aka.ms/mce-reviewappid)。按申请表当时要求提交 Client ID 等信息并等待批准。应用注册成功、设备码网页登录成功，都不能单独证明 Minecraft 服务已授权。
6. 启动页切到 **正版**，添加账号，按弹窗在微软网页输入设备码。账号须拥有 Minecraft Java 版或有效的对应订阅。验证首次登录、退出重开后的刷新登录，再启动游戏。

原有账号的 Refresh Token 与原 Client ID 相关；更换 ID 后，若刷新失败请重新网页登录。设备码申请、轮询及刷新令牌现在统一使用 Microsoft identity platform 的 `consumers/oauth2/v2.0` 端点。Minecraft 登录服务返回 403 时，同时排查应用授权与网络/IP 限制。

若保存后仍提示未配置，确认启动了新构建的 EXE，并完全退出旧进程。UI 仅显示配置状态，不会判断凭据是否有效或应用是否获批。

## 环境变量方式

保留 `PCL_MS_CLIENT_ID` 和 `PCL_CURSEFORGE_API_KEY` 的支持；**非空环境变量优先于本机配置**，改动后需重新启动进程。用户级环境变量还需从能继承新环境的终端/桌面会话启动应用。清除页面中的 Key 不会删除环境变量。日常使用推荐百宝箱配置，避免在命令行历史中留下 Key。

清空 Client ID 输入框后保存可移除本地 Client ID。更改本地配置不会改变已启动进程中的凭据；重启后生效。

## 百宝箱中的工具

- **重新搜索 Java**：复用现有 Java 检测流程，结果可在“设置 → 启动”查看和选择。
- **导入整合包**：复用现有整合包导入流程，选择本机整合包文件后安装。
- **打开游戏文件夹**：打开当前选中的 Minecraft 根目录，包含该根目录的版本与共享资源。
- **打开启动器日志**：打开启动器旁的 `PCL` 目录，查找 `Log1.txt` 等日志。
- **自定义下载**：填写 HTTP/HTTPS 地址，确认保存位置后加入现有下载任务列表，可查看进度或取消，不自动执行文件。主页自定义事件“下载文件”也复用此实现。

没有恢复原作者未公开的清理垃圾或内存优化实现；这些功能未放入新工具面板。更新、联网通知及主题切换保持原有实现。

## 开发验证

配置逻辑与凭据目标域名检查：

```sh
dotnet run --project tests/ServiceConfiguration.Checks --framework net10.0
dotnet build tests/ServiceConfiguration.Checks --framework net48
```

该检查程序链接实际配置模块，使用虚构输入，覆盖 Client ID 校验、HTTPS API 域名校验、环境变量优先级与输入错误。它不操作 Windows 注册表，不验证 DPAPI 存储，不调用真实服务；在 Linux 上出现 Windows 平台分析提示属于预期。

Windows 上使用支持 C# 13 的 Visual Studio 2022/MSBuild、.NET 桌面开发工具和 .NET Framework 4.8 Developer Pack，先 `dotnet restore PCLCS/PCLCS.csproj`，再构建：

```powershell
msbuild "Plain Craft Launcher 2\Plain Craft Launcher 2.vbproj" -p:Configuration=Debug
```

运行新构建的 EXE，检查百宝箱全部按钮、保存/清除/留空保留、重启后的配置读取，以及上面的真实服务流程。Windows 界面、DPAPI 与外部授权需在该环境验证；Linux 的配置检查或库编译不能替代这些检查。

本次验证：26 项配置检查通过，配置模块的 net48 检查工程编译通过，PCLCS 及其两个核心库编译通过，改动的 VB 文件无语法错误，百宝箱 XAML 的 7 个具名按钮均有 Click 处理程序。完整 VB 主工程在 Linux 上仍停在现有 `Resources.resx` 的文件路径大小写问题（`resources/custom.xaml` 与实际 `Resources/Custom.xaml`）；没有产出或验证新的 Windows 主程序 EXE。
